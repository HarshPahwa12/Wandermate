# WanderMate (MVP)

Reddit-style board for casual, low-pressure plans: a walk, a coffee, a board-game night.
Post a plan, browse plans near you, request to join, and the host approves who comes.

**Stack:** Spring Boot 4 (Java 21) · Spring Security + JWT · Spring Data JPA · Next.js 16 · Tailwind 4

## What works
- Register / log in (JWT, BCrypt)
- Post a plan: title, category, public spot, coordinates, time, guest capacity
- Nearby feed: distance-sorted within a radius (bounding-box query + Haversine), category filter
- Join requests with host approval; capacity is enforced under a row lock, so concurrent accepts can't oversell
- Host sees requests; guests can cancel or leave
- Safety and trust: hosts approve guests and see each requester's rating, meetup count and no-shows; hosts mark no-shows after a plan; exact meeting spots (and exact pins) are only shown to the host and accepted guests, everyone else sees an area label and a ~1 km rounded position; block and report
- Map + cards home: filters and plan cards beside a Leaflet map with category-coloured pins
- Switched off in the UI for now (backend support is still there): Google sign-in and the forgot-password flow (emailed reset link, 30 min, single use, rate-limited; logs the link when `SMTP_HOST` is unset). Re-enable by uncommenting the marked blocks in `frontend/app/login/page.tsx`
- Real-time chat over WebSocket (STOMP at `/ws`):
  - Group chat per plan for the host and accepted guests (membership follows accept / leave)
  - Direct messages, allowed only between people connected through a plan (host and requester, or two accepted guests)
  - JWT checked on STOMP CONNECT; subscriptions are authorised per conversation; sends are rate-limited
  - History, unread counts and read state over REST; live delivery and inbox notifications over WebSocket
  - Scaling: in-memory broker by default; set `CHAT_BROKER=relay` plus `CHAT_RELAY_*` to fan out through RabbitMQ (STOMP plugin) so several instances share chats

## Run it

### 1. Backend (port 8080)
The app talks to Supabase Postgres. Copy `backend/.env.example` to `backend/.env` and fill in the database and `JWT_SECRET` values, then:

```powershell
cd backend
.\mvnw.cmd spring-boot:run
```

(The integration tests use an in-memory H2 database through the `h2` profile; the app itself does not.)

### 2. Frontend (port 3000)
```powershell
cd frontend
copy .env.example .env.local
npm install
npm run dev
```
Set `NEXT_PUBLIC_API_URL` in `.env.local` if the backend isn't on `http://localhost:8080`.

Do not run `npm run build` while `npm run dev` is running: both write to `.next`.

## Deploy: Render (backend) + Netlify (frontend)

Order matters because each side needs the other's URL.

1. **GitHub.** Push this repo (`backend/` and `frontend/` together). Secrets never go in git: `.env` files are ignored, and only the `*.example` files are committed.
2. **Render (backend).** New -> Blueprint -> select the repo; it reads `render.yaml` (Docker service from `backend/Dockerfile`, region Singapore, health check `/api/health`). When asked, enter:

   | Variable | Value |
   |---|---|
   | `DB_URL`, `DB_USER`, `DB_PASSWORD` | Supabase -> Connect -> **Session pooler** |
   | `CORS_ORIGINS`, `FRONTEND_URL` | leave a placeholder, fill in after step 3 |

   `JWT_SECRET` is generated by Render. Copy the service URL (`https://wandermate-api.onrender.com` or similar).
3. **Netlify (frontend).** Import the repo; `netlify.toml` sets base `frontend`. Add the environment variable `NEXT_PUBLIC_API_URL` = the Render URL, then deploy. It is baked in at build time, so changing it needs a redeploy. Try a deploy preview first: Next 16 with `cacheComponents` is not confirmed on Netlify's adapter.
4. **Back to Render.** Set `CORS_ORIGINS` and `FRONTEND_URL` to the Netlify URL (https, no trailing slash) and redeploy. CORS and the chat WebSocket both read `CORS_ORIGINS`; the frontend derives `wss://` from `NEXT_PUBLIC_API_URL`.

Notes:
- Render's free tier sleeps after 15 minutes without traffic and takes about a minute (longer for Java) to wake; open chat connections drop while asleep.
- `JAVA_OPTS` (default `-Xmx320m -XX:+UseSerialGC -XX:TieredStopAtLevel=1`) is tuned for a 512 MB instance.
- Tables are created by Hibernate (`ddl-auto=update`). New tables need Row Level Security enabled by hand in Supabase.
- Google sign-in and forgot-password stay off until you uncomment them and set `GOOGLE_CLIENT_ID` / `SMTP_*`.

## API
| Method | Path | Notes |
|---|---|---|
| POST | `/api/auth/register`, `/api/auth/login` | returns `{token, user}` |
| GET | `/api/plans?lat&lng&radiusKm&category` | public; omit lat/lng for all upcoming |
| GET | `/api/plans/{id}` | host also gets the request list |
| POST | `/api/plans` | auth |
| POST / DELETE | `/api/plans/{id}/join` | request / cancel |
| POST | `/api/requests/{id}/accept`, `/decline` | host only |
